## 最新動向（10/23 19時時点）

最新の公表・続報の日付が新しい順に並べる。続報が出た事案は、最新の続報日の位置に移す。

- **佐川急便（10/23第5報）**：9/30に確認した「お荷物問い合わせサービス」への不正アクセスについて、漏えいの可能性がある件数を最大約5,323万件と公表した。6/21〜9/30の送り状データ（依頼主・届け先の氏名、住所、電話番号）、運賃契約者、Webサービス「スマートクラブ」登録者（メールアドレス、会員IDを含む）が対象。件数は重複を含む延べ件数で、対象人数ではないと説明している。手書きの送り状、クレジットカード情報、パスワードは対象外。不正利用は確認されていない。手口は「第三者による不正アクセス」とするのみ。お荷物問い合わせサービスは10/23に再開したが、問い合わせAPI、飛脚宅配便受付などは停止が続く（[Impress Watch](https://www.watch.impress.co.jp/docs/news/2150818.html)）。
- **ブラストメール（10/21〜23）**：ラクス子会社ラクスライトクラウドのメール配信サービスで、10/21未明に不審なアクセスを検知し、0:30に管理画面・APIを、1時頃に配信を停止した。第三者がAPI用サーバー2台に侵入してコマンドを実行し、全契約者の販売管理情報（会社名、担当者名、電話番号、メールアドレス、契約・支払い履歴）と、一部契約者の配信先リストを持ち出した。侵入経路は調査中で、再開は未定。利用組織の公表が続いており、新潟日報社（最大約25.3万人）、JR四国（最大約3万件）、岡崎市（約2.6万件）、横浜市（6,334人）などが公表した。公表先の一覧は10/23 13:45時点で76項目（[セキュリティ対策Lab](https://rocket-boys.co.jp/security-measures-lab/blastmail_20261022_summary_updated_23_public_notices/)）。利用企業タミヤの10/23 15時の追記によると、ラクスライトクラウドは漏えいが確認された対象288件への個別連絡を完了したと報告している（[タミヤ](https://www.tamiya.com/japan/newstopics/news_1982)）。
- **お名前.com デスクトップクラウド（10/21〜23）**：10/19に顧客の問い合わせで調査開始、10/20に不正プログラムの設置を確認、10/21 4:00から全プランを順次停止。第2報（10/22）で、取引ツール（MT4/MT5等）に保存された口座ログイン情報が取得され、取引口座で第三者による不正な操作が行われたとの報告を受けていると公表。10/22に警察へ相談。影響の可能性があるサーバーは26,739件。侵入経路は調査中。10/23 16:10時点の第3報では、26,739件は「対象となり得るサーバー数」であり、不正アクセスや情報取得が確認された件数ではないと明記した。侵入経路、個別の情報取得や不正利用の範囲は調査中で、再開は未定（[GMO第3報](https://group.gmo/info/alert/20261023/)）。
- **PHP2Shell（CVE-2026-109618/109619、CVSS v4.0 9.2、未認証RCE、10/21〜23）**：10/21に修正版（8.5.12/8.4.27/8.3.36/8.2.35）が公開。8.1以前は公式修正なし。国内ではエックスサーバー、BASE、カラーミーショップ、さくらインターネット、Movable Typeクラウド、お名前.comレンタルサーバー、Studioなどが予防停止・パッチ適用を公表。楽天市場や気象庁なども緊急メンテナンスを実施。**10/23 19時時点でこの脆弱性による国内の侵害を公表した組織はなく、バルテックの訂正によりゼロのまま。**なお、一部のまとめで「PHP2Shellの実害」として挙げられた大学サイトの改ざんは、大分大学が2024年の事案、琉球大学が10/9公表のCMS脆弱性によるもので、PHP2Shellとは別件である。また10/23の報道によると、Amazonは、公表4日前の10/17にハニーポット「MadPot」で悪用の試みを検知していた。発信元は商用の匿名化ネットワークに関連するIPアドレスで、攻撃者が公表前にどう情報を得たかは不明。Amazonは、少なくとも10/17以降を侵害調査の対象にするよう求めている（[ITmedia](https://www.itmedia.co.jp/news/article/2610/23/2000002530/)）。

## 結論サマリー

1. **全体像**：2026年は上場企業の100万件超漏えいが10月5日時点で10件となり、2025年通年の6件をすでに上回った（東京商工リサーチ）。その後も10月だけでソースネクスト（2,252万）、バーガーキング（1,118万）、カプコン（1,177万・全世界）、skyticket（1,464万）と1,000万件級が続き、本レポートの主要64事案のうち1,000万件超は8件にのぼる（レコード数のEPARK 約2,218万、延べ件数の佐川急便 最大約5,323万を含めると10件）。10/23には佐川急便が件数を最大約5,323万件（重複を含む延べ件数で、人数ではない）と公表し、公表件数としては2026年最大となった。10/21にはリクルート「カーセンサーnet」（最大約371万件）も加わった。
2. **最多の手口**：Webアプリ・APIの脆弱性や仕様・機能の悪用が最も多い（主因として18件）。内容は、内部APIの不正利用、アプリ解析によるAPI特定（A2B攻撃）、管理機能の不正操作、既知・未知の脆弱性悪用である。
3. **未公表率**：主要64件のうち、具体的な手口まで公表されたのは20件（31%）にとどまる。「不正アクセス」「調査中」のみで侵入経路が完全に未公表なのが23件（36%）、「侵害部位や委託先名だけ公表」が21件（33%）で、手口が特定できないものは合計44件（69%）に達する。
4. **波及構造**：KDDI（ISP6社）、Eストアー（7,858店）、IDCFクラウド（495組織）、スカラ「i-ask」（最大5社）、Studio（全登録顧客、デジタル庁を含む）、コミューン（LINEヤフー・Sansan・パナソニック等）、ブラストメール（新潟日報社 最大約25.3万人、JR四国 最大約3万件、横浜市など公表先76項目）など、委託先・SaaS・クラウド基盤の1件の侵害が多数の組織へ広がった。
5. **AIの確定度**：攻撃インフラ上でのAI利用は「確認」済み（JPCERT/CC 10/15、GMOイエラエ 10/19）。個別漏えい事案への関与は「推測」の段階にあり、被害企業・国による公式な紐付けは10月23日19時時点でない。
6. **PHP2Shell（CVE-2026-109618/109619）**：10月22日にバルテックが「PHPの脆弱性を標的とした攻撃」と公表したが、同日夜に「自社サービス自体の脆弱性」と訂正。**国内でPHP2Shellによる侵害を公表した組織は10月23日19時時点でゼロ**のまま（Cloudflareは公開後2時間で数十万件、その後数百万件の攻撃試行を観測）。Amazonは公表4日前の10/17に悪用の試みを検知しており、侵害調査は10/17以降までさかのぼる必要がある。
7. **ランサムウェア**：警察庁統計で2026年上半期は123件と半期最多（製造業37件、中小企業79件）。侵入経路はVPN機器が最多で、大量漏えい（Web/API層）と業務停止（VPN/RDP層）の二層構造になっている。

## 1. 調査方法と「原因の確定度」の定義

- **対象**：2026年1月1日〜10月23日19時に国内組織が公表した事案のうち、①影響10万件以上、または②業務停止・社会的影響が大きいものを「主要事案」として64件を抽出した（IDCF波及先のイズミとマウスコンピューター、上新電機とセカンドリテイリングはそれぞれ1行にまとめた）。
- **除外**：メール誤送信・媒体紛失などの単純な人為ミス（例：九州電力送配電の外部記憶媒体所在不明）、内部不正（ユナイテッドアローズ元従業員の持ち出し）、海外子会社のみの事案（エイチ・アイ・エスのタイ現地法人）、攻撃者の主張のみで企業が確認していないもの。
- **手口の型**：各事案に「主因」を1つ割り当てた。委託先・基盤経由は別途「波及」として第5章で集計した。
- **原因の確定度**：
  - **A（手口公表）**：脆弱性・機能悪用・認証情報の窃取など、具体的な手口が公式に示されたもの
  - **B（部位のみ）**：侵害されたシステム名、委託先名、ランサムウェアであることは公表されたが、侵入手口が未公表のもの
  - **C（未公表）**：「不正アクセス」「調査中」のみのもの
- **出典の扱い**：各社公式発表と専門メディア（ITmedia、INTERNET Watch、ScanNetSecurity、Security NEXT、piyolog、日経、NHK等）を優先。民間まとめサイト（westeria.jp、satimo.org、directcloud.jp等）のみに依拠する数字は「未確認」と明記。

**手口の型（凡例）**

| 型 | 内容 |
|---|---|
| ① | Webアプリ・APIの脆弱性、仕様・機能の悪用（A2B攻撃、SSRF、認証なしAPI、アプリ埋め込み鍵、管理機能の不正操作） |
| ② | 盗まれた・弱い認証情報（フィッシング、委託先PC感染、管理アカウント乗っ取り） |
| ③ | 委託先・SaaS・クラウド基盤経由の波及（起点側の手口が不明なもの） |
| ④ | 設定・管理の不備 |
| ⑤ | VPN・リモートアクセス機器の脆弱性 |
| ⑥ | ランサムウェア |
| ⑦ | 侵入経路未公表・調査中 |

**読み方**

- 侵入経路が完全に未公表なのは36%で、手口が分からないもの（B＋C）は69%に達する。⑦の27件にも、焼肉きんぐ、バーガーキング、セイコーマート、H2O、カプコンのように「公式アプリ・会員管理システム・予約サイト・アカウント基盤」が侵入部位として示されたものが多い。JPCERT/CCの類型B（API経由の不正操作）やNICTのA2B攻撃と同じ系統である可能性は高いが、各社が手口を公表していない以上、これは**推測**にとどまる。
- 民間集計も同じ傾向を示す。westeria.jpの2024〜2026年124件の手口タグでは「不正アクセス（経路未公表）」が34件で最多だった（Webサービス・アプリ経由26件、委託先・取引先経由28件、ランサムウェア27件、盗まれた・弱いID/パスワード17件、VPN・リモートアクセス機器13件、設定・管理不備10件。複数タグあり）。
- **⑤VPNが少ない点は「秋の漏えいラッシュ」の特徴であり、年間のランサムウェア全体では逆になる**。警察庁統計では、2026年上半期のランサムウェア感染経路（有効回答36件）はVPN機器18件、リモートデスクトップ9件だった。大量の個人情報漏えいはWeb・API層、業務停止型のランサムウェアはVPN・RDP層という二層構造である。

## 6. なぜ2026年秋に集中したのか

### 6-1. 公的機関の見解（分かっていること）

- **JPCERT/CC（10/8注意喚起、10/9更新）**：「2026年9月前後」に漏えいが相次いでいるとしたうえで、技術的な情報の共有が不足しており把握している情報は限定的かつ断片的と記した。示された4類型は、A：既知脆弱性の探索と管理不備（環境設定ファイルやバックアップの窃取）、B：API経由の不正操作（アプリ解析によるAPIキー特定、内部APIへの攻撃、NoSQLインジェクション、他システムから窃取したAPIキーの使用）、C：MetabaseのSQLインジェクション（CVE-2026-72898、ゼロデイ攻撃あり）、D：WARファイル型Webシェル。ただし「すべての事案で同一の攻撃手法が使用されていることを示すものではない」と限定している。
- **JPCERT/CC（10/15調査、[JPCERT/CC Eyes](https://blogs.jpcert.or.jp/ja/2026/10/web_api_attacks.html)）**：攻撃インフラの調査で、攻撃者がAIを利用して既知の脆弱性のスキャンやAPI経由での攻撃を実施していたことを確認。攻撃元サーバーにはAPK解析の痕跡、SSRF検証用スクリプト、Flutter解析ツール関連ファイルがあり、日本以外向けのサービスも攻撃していた。どの被害事案かは示していない。
- **NICT（10/13、[注意喚起](https://www.nict.go.jp/press/2026/10/13-1.html)）**：相次ぐ漏えいの「原因の一つ」として「A2B攻撃（App-to-Backend Attack）」を特定。Google Playの日本地域で公開されたAndroidアプリを解析し、接続先サーバーの仕様に合わせて攻撃する手口で、アプリ自体に脆弱性がなくてもサーバー側の認証・認可の不備で漏えいし得る。
- **個人情報保護委員会（10/7）**：WARNINGを改訂し、事例9「APIが悪用される事例」を追加。管理外のAPI、パラメータ書き換えで他人のデータにアクセスできる状態、連番ID、レートリミットの欠如を原因として挙げる。
- **IPA（10/9）**：特定のプロダクトやサービスの脆弱性を狙った攻撃とは断定されておらず、外部公開アプリとアカウント侵害が起点とみられるとした。10/16には事業者向け「不正アクセス特別相談窓口」を開設。
- **国家サイバー統括室（10/9）**：事案を複数確認とし、経営層の関与を求めた。10/14には各機関の注意喚起を1ページに集約。
- **警察庁長官（10/8）**：現時点で事案の背景や相互の関連性は明らかではないと発言。10/15には流出メールアドレス宛ての偽メールに注意を呼びかけ。
- **デジタル大臣（10/2）**：不正目的のおそれによる漏えい等の報告件数は令和6年度7,604件、令和7年度3,822件で、必ずしも増加傾向にあるわけではないと説明。10/6にはパスワード使い回しの中止、多要素認証、不審メールへの注意の3点を国民に要請。
- **官房長官・首相（10/6〜8）**：「大変深刻に受け止めている」と発言。10/8に全府省庁の関係省庁会議があり、国家サイバー統括室に情報を集約。10/21〜22のPHP2Shell対応では高市首相が各組織に対応を呼びかけ、楽天市場・気象庁・ドコモなど多くのサイトが予防的に公開停止・緊急メンテナンスを実施した。
- **総務省・経産省・金融庁（10/9）**：総務省は所管事業者と自治体に注意喚起。経産省は約1,000の業界団体を通じて注意喚起し、提供された情報を同意なく公表しないとした。金融庁は非対面本人確認の徹底を要請。

### 6-2. 専門家・民間の見方（推測・観測を含む）

- **マクニカら3社の共同資料（10/7）**：攻撃の特徴を「特定の脆弱性だけを探すのではなく、サイトやAPIの不備を広く探る動き」と整理。AIについては断定できるログや痕跡は確認されていないとしつつ「AIの活用を否定する方が難しい状況」とし、ゼロデイがAIで発見・悪用されている状況は確認されていないとした。
- **サイバーセキュリティクラウド（10/9）**：同一とみられる攻撃者が約40分間に326のIPアドレスを使い分け、1,200件超のアクセスを行ったと報告。AIエージェントの可能性を挙げたが、AIの利用を直接示す痕跡を確認したものではないと明記。
- **GMOサイバーセキュリティ byイエラエ（10/19、[ScanNetSecurity](https://scan.netsecurity.ne.jp/article/2026/10/21/56522.html)）**：攻撃元インフラでAI自律型ペネトレーションテストシステム「ARTEX」（中国で開発されたとされ2026年7月にOSS公開、悪用報道を受け10月に公開取りやめ）の使用を確認。標的は日本企業約20社で、うち9社は同業種。同種のAI攻撃インフラを新たに6台発見し、台ごとに主な標的業種が分かれていた。標的企業のうち8社は9〜10月に漏えいを公表済み。**注意点**：約20社すべてが侵害されたわけではなく、8社の社名は公表されていない。
- **ラック（10/15）**：国内法人のWebシステム・アプリ関連の漏えい公表は10月6日時点で119件、うち81件（約68%）が7月以降。同社のサーバー不正侵入対応案件は前四半期の30%から7〜9月は52%に上昇。一方、認知から初回公表までの平均日数は5月の10.9日から9月は2.9日に短縮し、JSOCの不審通信は長期的に大幅増とは評価しにくいとした。倉持CTOも開示時期が9月末に重なった面が大きいとの見方を示している。
- **Cloudflare（10/21〜22）**：PHP2Shellの保護ルールを公開約9時間前から有効化。公開から2時間で数十万件、その後数百万件の攻撃試行を観測。攻撃者はルール回避のためペイロードを変異させ始めており、WAFがあってもパッチ適用を推奨。
- **警察庁の観測**：脆弱性探索などの不審アクセスは2026年上半期に1日・1IPアドレス当たり13,687件で、前年同期比50.7%増。秋のラッシュ以前から探索が増えていたことを示す一次統計。

### 6-3. 本レポートの判断

- **確認されたこと**：①Web・APIの基礎的な不備（認可、レート制限、管理機能の露出、アプリ埋め込み鍵）と既知脆弱性の広範な探索、②攻撃インフラ上でのAI利用（JPCERT/CC、GMOイエラエ）、③探索アクセスの前年比約1.5倍の増加、④7月以降の公表数の急増。
- **推測にとどまること**：個別の大型事案（タイムズカー、焼肉きんぐ、ソースネクスト、カプコンなど）が同一グループやAIによるものかどうか。被害企業・国による公式の紐付けはない。
- **結論**：秋の集中は、①7〜9月に実際に増えた自動化・AI支援型のWeb/API探索と、②9月末〜10月に調査結果・開示・続報が一斉に出たことの複合である。加えて、③政府の注意喚起（10/7〜9）を受けた点検で過去の侵害が掘り起こされた面もあるとみられる（③は本レポートの推測）。デジタル大臣が示した年度件数の減少は2025年度までの数字で、2026年7月以降の急増を反映していない点に注意が必要である。

## 8. 被害を受けた側・利用者への影響

- **免許証画像の流出と本人確認制度**：タイムズカーで約160万件の本人確認書類画像が流出。愛知県（10/1）と新潟県（10/2）の公安委員会は流出対象者に特例で免許証の再交付（番号・顔写真の変更）を認めた。金融庁は10/9、2027年4月1日施行の犯収法施行規則改正（画像送信方式を廃止しICチップ読取に原則一本化）を施行日を待たず前倒しするよう金融機関に要請。
- **パスワード使い回しによる実害**：infoQでポイント不正交換611件・計2,869,500円分（10/5時点）、お名前.comでFX・証券口座の不正操作報告、カプコンで196件のパスワード不正変更、ソースネクストはパスワードを含む最大2,252万件、KDDIはメールパスワード約762万件。
- **フィッシングの警告**：警察庁は10/15、流出したメールアドレスに届く漏えい元企業をかたる偽メールへの注意を呼びかけた。日経では社員アカウントからなりすましメール約9,000件が送信され、それを起点に日経BPでも認証情報が窃取された。漏えいがフィッシングを生み、それがさらに漏えいを生む連鎖が実際に起きている。
- **業務停止の影響**：IDCFの利用495組織、京王の決済・ポイント、大阪公立大学の約1週間の休講、電子書籍2サービスの全面停止、バルテックの業務SaaS20以上、ブラストメールのメール配信全停止、メドレー@linkを使う医療機関など、漏えい件数に表れない損失が大きい。

## 9. 構造的な問題点

1. **「公開アプリ＝サーバー仕様の地図」問題**：アプリに埋め込まれたAPIキーや秘密鍵、クライアント側の処理を前提にした認証、サーバー側の認可（誰のデータか）の欠落が、A2B攻撃と大量取得を許した。
2. **集約された会員基盤・共有基盤**：1つの会員IDやマルチテナント基盤に顧客情報を集めた結果、1回の侵害が1,000万件級、数千店舗級の被害になった。
3. **不要データの保持**：skyticketの2018年以前の決済ログ、タイムズカーの退会者の免許証画像の長期保管など、「消していなかった」ことが被害を広げた。
4. **開示の質のばらつき**：主要事案の67%で手口が分からず、他社が教訓を引き出せない。JPCERT/CCも技術的な情報の共有が不足と明言している。
5. **最大値ベースの初報と後からの訂正**：JR東日本・JR九州の「漏えいなし」、skyticketのカード情報の追加、Eストアーの件数修正、バルテックの原因訂正、コロナの下方修正（3.5万→2.4万人）など、件数・項目・原因が続報で大きく動いた。

## 10. 示唆

**事業者向け（優先順）**

1. 直近1か月、続けて3か月分のAPI・管理機能のログを点検する。見る点は、大量取得、403/404/503の急増、作った覚えのないアカウント（IPA・専門家共同資料の推奨）。
2. 全APIを棚卸しし、エンドポイントごとの認可、レート制限、連番IDの廃止、レスポンスの最小化を行い、アプリへの秘密鍵の埋め込みをやめる（PPC事例9、JPCERT/CC、NICT）。
3. 委託先・SaaSを自社と同じ基準で点検する。管理サイトにフィッシング耐性のある多要素認証を入れ、テナントを分離し、委託先端末を管理する（i-ask、第一興商、NEC）。
4. 不要データ（退会者情報、本人確認画像、古いログ）を削除する。本人確認はICチップ読取に前倒しで移行する。
5. PHP2Shellなど既知脆弱性の緊急パッチを当てる。WAFがあることを理由にパッチの優先度を下げない。
6. 被害時は手口を含めて公表し、国家サイバー統括室や所管省庁へ技術情報を共有する。経産省は、提供された情報を同意なく公表しないとしている。

**個人向け**

1. サービスごとに異なるパスワードを使う（パスワードマネージャーに任せる）。ソースネクスト、KDDI、Gyazo、skyticket、カプコンの利用者は直ちに変更する。
2. 多要素認証を有効にする。特に証券・FX口座は必須。お名前.comデスクトップクラウドの利用者は、サーバー以外の端末から口座パスワードを変更する。
3. 漏えい元をかたるメールやSMSのリンクは開かず、公式アプリやサイトから確認する。
4. 免許証画像が流出した場合は、再交付の特例（各県公安委員会）の利用を検討し、身に覚えのない契約や信用情報を定期的に確認する。

## 留意事項

- 主要64件は網羅的な母集団ではなく、10万件以上または社会的影響が大きい事案を抽出したものである。構成比はこの抽出に依存する。民間集計では、9月25日〜10月8日だけで第1報36件（westeria.jp）、Web関連の公表119件（ラック、10/6時点）が確認されている。
- 数値の不一致：セイコーマート（572,022人／574,647人）、infoQ（894,082件／最大948,498件）、KDDI（1,223万3,087件／12,231,954件）は公表時点の違いと考えられるため併記した。
- 2りんかんイエローハット（3,179,454名、API悪用）、Klue（Salesforce連携悪用で国内外約24社）、ノーウェアランサム9件は、民間まとめサイトまたは単一の二次情報でしか確認できず、**未確認**である。
- 警察庁の上半期報告PDFは直接参照できず、内訳は複数の専門メディア・事業者による引用の一致で確認した。金融庁の数値は暫定値。
- 攻撃者による犯行声明のみの事案（IDCFに関するSNS上の声明など）は、事実として扱っていない。
- 日経「企業一覧」に10/21〜22公表として掲載されているが、本レポートで公式発表を照合できていないもの（エムスリー 約400件、富士急ハイランド、厚労省委託先の廃炉作業研修サイト）は**未確認**として本文に入れていない。10/23公表とされるSmartHRグループ、KOMOJU、システムファイブ、フジッコなどの小規模事案も、公式発表を照合できておらず**未確認**。
- 1,000万件超の件数は、人数・件数で示されたものを数え、レコード数（EPARK）と重複を含む延べ件数（佐川急便）は除いた。
